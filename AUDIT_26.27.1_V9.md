# MAX 26.27.1 V9 — Технический аудит мода

**Версия стока**: 26.27.1 (build 6802)
**Версия мода**: V9 (Privacy Mod by JohNick)
**Дата**: 2026-08-28
**Совместимость**: `ru.oneme.app` (Android 8.0–16.0 / API 26–36) · arm64-v8a + armeabi-v7a · основной + клон (`ru.oneme.ap2`)

> **V9**: продолжение объединённой линии разработки `26.27.1 GP e2e`. Весь функционал V8 сохранён без изменений. V9 сосредоточен на улучшении надёжности и UX E2E-слоя: постоянный артефакт сброса доверия в истории чата, понятное KEY-RECOVERY при смене ключа собеседника, fail-closed защита от утечки открытого текста, alpha-реализация шифрования аудиозвонков, фикс значка замка в тулбаре, исправление бейджа непрочитанных и два UX-улучшения экрана «О приложении».

## 🆕 26.27.1 V9 — что нового

### 🔄 Служебная плашка при сбросе E2E-доверия (Full peer-reset)

При сбросе доверия или E2E-сессии собеседника через профиль чата («🔄 Сбросить доверие» / «Удалить сессию») в историю чата теперь записывается **постоянное служебное сообщение** — видно в ленте после рестарта приложения. До V9 в этот момент показывался только исчезающий тост: пользователь мог не заметить, что сброс произошёл, и не знал, когда именно менять QR.

Техническая суть: сообщение вставляется через штатный механизм локальных системных сообщений чата при вызове reset-хука, с текстом «🔄 Сессия сброшена — обменяйтесь QR заново». Сообщение хранится в Room-базе чата и не исчезает при рестарте.

### 🔑 Понятное восстановление при смене ключа собеседника (KEY-RECOVERY)

Если собеседник переустановил мод или сменил телефон, его identityKey меняется — мод обнаруживает несоответствие при расшифровке. До V9 пользователь видел непонятную ошибку «битый QR» или `[E2E decrypt failed]` без объяснений.

В V9: при обнаружении изменения ключа собеседника мод показывает информативный диалог — что произошло (собеседник сменил ключ), что нужно сделать (сбросить доверие → обменяться QR заново). Три понятных шага вместо технического сообщения об ошибке. Sentinel: `# :key_recovery_dialog_v1`.

### 🔴 Fail-closed отправка

При выбранном режиме «🔒 Шифрование ВКЛ» (строгий режим) в профиле чата: если шифрование сообщения не удалось по любой причине (нет сессии, ошибка крипто-ядра, рассинхрон), сообщение **не отправляется открытым текстом**. Пользователь видит предупреждение и возможность либо починить шифрование, либо переключить режим.

До V9 при строгом режиме и технической ошибке шифрования сообщение могло уйти открытым — это была потенциальная утечка контента при нежелательном сценарии. Sentinel: `# :fail_closed_send_v1`.

### 📞 Экспериментально (alpha): сквозное шифрование аудиозвонков

Нативная крипта аудиоканала личных 1:1 звонков на тех же Signal-ключах, что и переписка. Отдельного тумблера для звонков нет — шифрование следует режиму E2E чата (глобальный флаг `e2eCalls` скрыт и инертен).

Условия активации: Signal-сессия установлена с обеих сторон + мод V9+ у обоих + режим шифрования чата не «ВЫКЛ». При несоответствии условий звонок проходит штатно без шифрования (не ломается). Индикатор 🔒 во время звонка = аудио зашифровано.

Функция помечена как alpha: поведение, способ активации и совместимость могут уточняться в будущих версиях. Только аудио (1:1). Видео и групповые звонки не покрыты.

### 🔒 Фикс значка «замок» E2E в заголовке защищённого чата

В V8 иконка замка 🔒 в тулбаре открытого E2E-защищённого чата не отображалась: компонент тулбара, отвечающий за отрисовку статусной иконки, использовал устаревший вызов, который возвращал null в текущей версии стока. В V9 вызов заменён на актуальный метод рендеринга иконки состояния; значок корректно появляется при активной Signal-сессии. Sentinel: `# :e2e_lock_icon_fix_v1`.

### 🔢 Фикс бейджа непрочитанных при «Невидимке» / анти-читалке

Локальный счётчик непрочитанных (бейдж в списке чатов) в ряде сценариев оставался зажжённым при включённом antiRead / smartAntiRead — даже когда чат был визуально просмотрен. Первопричина: гейт бейджа не учитывал состояние ledger'а прочитанных сообщений (`rl_<chatId>`) при одновременно активных флагах invisible и smartAntiRead.

В V9 гейт бейджа сделан ledger-aware: при решении показывать бейдж или нет учитывается как серверное состояние, так и локальный ledger. Счётчик гаснет корректно. Sentinel: `# :unread_badge_ledger_aware_v1`.

### ℹ️ Три информационные карточки на экране «О приложении»

На экране «О приложении» добавлены три информационные карточки с кратким описанием ключевых возможностей мода: приватность/невидимка, E2E-шифрование, антиудаление. Карточки показываются всегда без тумблера — ориентированы на новых пользователей и как быстрая справка. Реализованы как статические View-элементы, встроены через хук `AboutScreen.onCreateView`. Sentinel: `# :about_info_cards_v1`.

### 📝 Диалог «Проверить обновления» — рендер plain-text

Диалог автопроверки обновлений (`CheckUpdateDialog`) получал текст из GitHub Release Notes в формате Markdown и отображал его без обработки: символы решёток, звёздочек и буллетов были видны как есть. В V9 перед показом текст прогоняется через легковесный strip-преобразователь: markdown-заголовки становятся обычной строкой, парные звёздочки-акцент снимаются, остальные маркеры сохраняются. Итог — читаемый plain-text в диалоге. Sentinel: `# :update_dialog_markdown_strip_v1`.

## 🆕 Унаследовано из 26.27.1 V8 (без изменений)

### 🔐 Сквозное шифрование личных чатов (E2E)

Реализация на **Signal Protocol** (X3DH для установления сессии + Double Ratchet для forward secrecy на каждом сообщении). Ключи никогда не покидают устройство. Сервер MAX видит только шифротекст — сам протокол устойчив к компрометации сервера.

Активация — из меню личного чата (пункт **«Начать защищённый чат»**). Обмен pre-key bundle между устройствами — по QR-коду или deeplink. Верификация собеседника — сверкой отпечатка (fingerprint) в меню чата.

Подробная справка для пользователя — прямо в приложении: **«🔒 ПРИВАТ → E2E Шифрование»**.

Компоненты (все в отдельных smali-классах мода `one/me/e2e/*`, не пересекающихся со стоком):
- Крипто-ядро: X3DH-handshake, Double-Ratchet-state, HKDF-цепочки, message key derivation.
- Persistence: ключи в encrypted SharedPreferences, one-time pre-keys ротируются автоматически.
- Deeplink-bootstrap: обработка `max-e2e://…` для авто-подтверждения ключей.
- UI-слой: QR-скан, отображение fingerprint, статус защищённости в тулбаре чата.

Каналы и групповые чаты E2E пока не поддерживают (только 1-на-1). Сообщения, отправленные **до** активации E2E, остаются в исходном формате — новые шифруются.

Device-verified на HA218XJZ (Lenovo, 2026-08-24): wire-шифрование подтверждено, 31/31 unit-тест крипто-ядра PASS.

### 🖼 Фикс «Вид → Выбрать обои чата» — авто-включение прозрачности

При выборе новых обоев через пикер автоматически включается `transparentTheme` (или `transparentThemeChats`), после чего `ChatScreen` пересоздаётся — обои сразу видны без ручной настройки тумблера. Sentinel: `# :wallpaper_picker_autotransparent_v1`.

### 👍 Фикс «повторно всплывают уже просмотренные реакции» при «Невидимке» — reaction-ledger

Независимый ledger `rr_<chatId>` в `SharedPreferences("app_flags")`: при просмотре реакции запоминается `lastReactedMessageId`, при повторном рендере бейдж подавляется сравнением. «Невидимка» продолжает работать. Sentinels: `# :reaction_ledger_record`, `# :reaction_ledger_gate`, `# :gateReaction`.

## 🛡 Профиль приватности

### Невидимка (`invisible`) — мастер-переключатель

| Дочерний флаг | Что делает |
|---|---|
| `antiTyping` | собеседник не видит набор текста |
| `antiRead` | собеседник не видит отметку «прочитано» |
| `smartAntiRead` | «прочитано» уходит только после вашего ответа |
| `antiPresence` | онлайн / last-seen скрыты |

### Reaction-ledger (V8, без изменений)
`rr_<chatId>` в `SharedPreferences("app_flags")`. Активен при invisible OR (antiRead && !smartAntiRead) OR (smartAntiRead && chat opened). Не изменяет серверное поведение — только локально подавляет re-surface бейджа.

### Unread-badge ledger-aware гейт (V9, новый)
Гейт бейджа непрочитанных учитывает локальный ledger состояния при одновременно активных `invisible` + `smartAntiRead`. Sentinel: `# :unread_badge_ledger_aware_v1`.

### E2E (V8, без изменений)
Signal Protocol X3DH + Double Ratchet. Ключи никогда не покидают устройство, сервер видит только шифротекст.

### Fail-closed отправка (V9, новый)
При режиме «Шифрование ВКЛ» — сообщение не уходит открытым при невозможности зашифровать. Sentinel: `# :fail_closed_send_v1`.

### Антиудаление (`antiDelete`) — 4 слоя
1. **L3** — Central WS chat-event. 2. **L4** — Room ORM body-clear. 3. **Маркер** ❌ + время удаления. 4. **FCM офлайн-персист**.

### Нейтрализация телеметрии
Чокпоинты в push-транспорте, aggregation-логах, operator-fetch (IP-strip), DPS-пинге.
