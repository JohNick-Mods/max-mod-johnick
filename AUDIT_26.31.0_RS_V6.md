# MAX 26.31.0 RS V6 — Технический аудит мода

**Версия стока**: 26.31.0 RS

**Дата**: 2026-09-18
**Совместимость**: `ru.oneme.app` (Android 8.0–16.0 / API 26–36) · arm64-v8a + armeabi-v7a · основной + клон (`ru.oneme.ap2`)

> **V6**: точечный релиз поверх V5 (v26.31.0.5). Добавлено: скролл к закреплённому сообщению в группах при промахе локальной БД (F18), убран стоковый self-update офф-клиента с экрана «О приложении» + собственная карточка автопроверки обновлений мода (F19), гейт отключения входящих звонков (A2), порог показа кнопки скорости воспроизведения для коротких медиа (A4), дублирующая стоковую кнопка «Поделиться логами» в настройках мода (A6). Полный fan-out аудит всех ~247 активных `apply_v_*.py` по 10 направлениям, сверка находок с реальным логом сборки — критических багов в собранном APK не найдено. Предыдущий публичный релиз — 26.31.0 RS V5 (2026-09-18).

## 🆕 Новые функции V6

### 📌 Скролл к закреплённому сообщению в группах (F18) — FIXED

**Проблема**: в группах со «старым» закреплённым сообщением (уже вне загруженного окна ленты) тап по пин-бару ничего не делал — `Lxab;->c()` при промахе локальной БД тихо возвращался, в logcat писал `«Trying to scroll for non-existing messageId=»`.

**Фикс**: `apply_v_pin_scroll_fix.py` — сетевой догруз тем же пайплайном, которым пользуется сам пин-бар (`Lux7;->a` → `Lu44;->x0` → `Lmab;->m` → `Lsua` → штатная ветка скролла). Kotlin-continuation `Lxab` расширена полем `j:J` (chatId) и суспенд-состояниями 2/3. Закрыты два неочевидных капкана с затиранием регистров v6 (continuation) и v0 (owner-объект) — задокументированы в `MEMORY/lessons_pin_scroll_state_machine_20260918.md`. Независимая адверсариальная верификация — чисто. Sentinel `:sar_pin_v1_fetch_setup`.

### 🚫 Убран стоковый self-update офф-клиента (F19) — FIXED

**Проблема**: на экране «О приложении» мода показывался стоковый self-update-блок офф-клиента (карточка «Новая версия / 26.32.1», строка «Скачать обновление», строка «Последнее обновление: N дней назад») — мод фактически предлагал пользователю уйти на официальную сборку поверх себя.

**Фикс**: `apply_v_hide_stock_updater.py` — три branch-редиректа в билдере айтемов `Lh0;->r(Ljava/lang/Object;)` (c3/h0.smali), каждый превращает существующий условный переход в безусловный `goto/16` на уже существующую метку того же метода. Без вырезания кода (метод ~1243 строки с плотным реиспользованием регистров) — новых рёбер CFG не появляется, `VerifyError` по слиянию типов невозможен по построению. Не тронуты: «Версия приложения», «Отправить отчёт», тумблер «Автообновление» (зеркалит флаг мода). Sentinel `:sar_hide_stock_upd_v1`.

### 🔄 Своя карточка проверки обновлений мода (F19, продолжение) — NEW

На месте убранного стокового блока — карточка мода: автопроверка при открытии экрана «О приложении» (фоновой `Thread` → существующий `UpdateChecker.fetchReleasesWithFallback`, 4-уровневый fallback GitHub API → raw → HTML → codeberg, таймауты 10/15с), результат через `Handler(mainLooper)`. Троттлинг 5 минут. Все сетевые/UI-операции в try/catch — экран не роняется при ошибке сети. Тап при наличии обновления сразу запускает существующий путь скачивания. Собственный HTTP-клиент не вводился — переиспользован публичный API `UpdateChecker`. `apply_v_update_card.py`, sentinel `:card_autocheck_v1`. Device-verified Redmi: карточка отработала автопроверку, показала «Установлена последняя версия».

### 📵 Отключение входящих звонков (A2) — NEW

Тумблер «Отключить входящие звонки» (категория Система → Звонки): `apply_v_disable_incoming_calls.py` — инъекция в `c3/ygj.smali` рядом со стоковой веткой игнорирования звонка (`«incoming call ignored: disabled via debug setting»`). Итоговое условие — `v5 = stock_flag OR AppFlags.disableIncomingCalls`, существующая ветка игнорирования не изменена. `.registers` не бампается. Device-verified Redmi: тумблер переключается, без крашей.

### ⏱ Порог показа скорости воспроизведения (A4) — NEW

RadioChoice-тумблер (5 вариантов: 30 сек/60 сек/5 мин/10 мин + выкл): `apply_v_min_duration_speed.py` — гейт в `c1/jb3.smali::r()` перед созданием `PlaybackSettingsBottomSheet`, сравнивает длительность медиа (`Luzj;->getDuration()J`) с порогом; для коротких медиа возвращает Kotlin Unit без показа шторки. Реализовано через `packed-switch v19` (не `if-ne`/`const-4` — те опкоды ограничены 4-битным диапазоном регистров v0–v15, а свободные регистры метода — v15–v20; переписано на `packed-switch`/`invoke-interface/range`, не требующие 4-битных операндов). `.registers` не бампается. Device-verified Redmi: выбор порога сохраняется без краша.

### 📤 Кнопка «Поделиться логами» в настройках мода (A6) — NEW

Дублирует стоковую функцию «Отправить логи» (dev-меню) внутри настроек мода. Путь реализации — переиспользование готового обработчика, не написание своего сборщика логов: `sput-object p0, Lone/me/util/AppFlags;->stockShareLogsProvider:Lmrg;` захватывает живой Dagger-factory instance в `<init>` стокового провайдера (`c1|c3/mrg.smali`, положение класса в baksmali-дереве зависит от rebalance между c1–c4 — скрипт ищет по всем сегментам); `ModsShareLogs.show()` при непустом providerе вызывает `Lmrg;->b(null)` — та же цепочка, что и у стоковой кнопки (`Llcg`-корутина → архивация логов → `ACTION_SEND` + `createChooser`). При первом обращении (provider ещё не инициализирован Dagger'ом) — Toast с подсказкой открыть стоковую кнопку логов один раз. `apply_v_share_logs_button.py`, sentinels `:share_logs_provider_capture_v1` / `:share_logs_v1`. Device-verified Redmi: Toast-путь сработал корректно без крашей.

## 🔧 Баги, найденные и исправленные в процессе сборки V6

Три rebuild-hazard обнаружены при первых прогонах `make_v1.py --strict --e2e` для V6 и исправлены до попадания в релизный APK:

1. **Хардкод пути `c1/mrg.smali`** в `apply_v_share_logs_button.py` — в 26.31.0 класс `Lmrg;` оказался в другом сегменте dex (rebalance между c1–c4). Скрипт переписан на поиск по всем сегментам.
2. **Устаревший anchor `showVerticalList`** в том же скрипте — якорь на `addView(v0, v2)` перед «Настройки MAX» был смещён более ранним патчем (`apply_v_troubleshoot_button.py`, STEP 126), реальная точка вставки сдвинулась на `addView(v0, v3)`. Якорь и replacement обновлены.
3. **Register-format баг в A4** (`apply_v_min_duration_speed.py`): опкоды `const/4`/`if-ne`/`invoke-interface {vN}` требуют 4-битных операндов (v0–v15), а патч использовал свободные регистры v19/v20 вне метода `jb3.smali::r()` (`.registers 26`). `smali.jar` валил ассемблинг с `Invalid register`. Переписано на `packed-switch v19` (31t, 8-бит) + `invoke-interface/range` (3rc, 8-бит) — не требуют 4-битных операндов, `.registers` не бампается.

Дополнительно смягчены два FATAL→WARN перехода в `apply_v_transparent_theme.py`/`apply_v_chats_transparent_flag.py`: якорь DESCS-подсказки (описание тумблера в HashMap) сместился после добавления новых тумблеров между `troubleshoot` и `e2eMessages` — сама подсказка не критична для работы тумблера (поле+reload+apply гейтированы отдельным FATAL-чеком), поэтому промах якоря подсказки больше не останавливает сборку.

## ✅ Fan-out аудит перед публикацией

Все ~247 активных `apply_v_*.py` (входящих в `APPLY_STEPS`/`E2E_ONLY_STEPS`/`CALL_E2E_ONLY_STEPS`/`DEFERRED_STEPS` текущего `make_v1.py`) проверены 10 параллельными агентами по тематическим группам (E2E/call-e2e, hide/search-hide/filter, misc ×3, ringback, scroll/antiread, telemetry/vpn, theme/wallpaper, watch/antidel/export/security). Проверялось: (а) вызовы всех определённых функций внутри `main()`, (б) приземление сентинелов патчей в `work/baksmali`, (в) отсутствие «wired-but-undefined method», (г) актуальность smali-якорей относительно текущего дерева (R8-drift).

Часть первичных находок субагентов (устаревшие статические таблицы `r8_mapping.py`, «ANCHOR-NOT-FOUND» на уже применённых идемпотентных патчах, ложные FATAL-заявления при неверном чтении кода) были перепроверены вручную сверкой с реальным успешным логом сборки `build_v6_final.log` — во всех случаях реальное поведение сборки штатное (патч либо уже применён — SKIP, либо скрипт сознательно закомментирован/исключён из активного пайплайна с задокументированной причиной). Непойманных активных багов в собранном APK не найдено.

- **Сборка**: `make_v1.py --strict --e2e` — все 4 APK прошли gate (`exact_abi`, `no_tracer`, v2+v3 подпись `apksigner`, distinct arm64/armeabi-v7a SHA256 ассетов).
- **Статические gate**: `reg_collision_gate.py`, `type_ref_gate.py`, `undefined_method_gate.py`, `table_registration_gate.py`, `r8_drift_gate.py` — PASS (0 CRITICAL).
- **Method-refs**: classes.dex 96.6%, classes2.dex 94.2% от лимита 65535 — WARN (не критично для V6, следить в будущих версиях).
- **Device-verify Redmi (WGJBBEY9SSMN8TIB)**: main+clone установлены и запущены без FATAL/VerifyError/NoSuchMethod. F19 (карточка обновлений + отсутствие стокового блока) подтверждён визуально. A2 (тумблер) переключается без краша. A4 (radio-choice) сохраняет выбор без краша. A6 (Toast-путь) сработал как задокументировано.
- **Не покрыто device-тестом**: F18 (нет старого закреплённого сообщения в тестовых чатах), полный путь A4 через реальный видео-плеер (нет видео в тестовых чатах), полный путь A6 через живой стоковый provider (не найдена стоковая кнопка «Отправить логи» в очевидных местах Dev-меню за разумное время автономной проверки). Синтаксическая валидность всех трёх подтверждена успешной dex-сборкой и статическими гейтами.
