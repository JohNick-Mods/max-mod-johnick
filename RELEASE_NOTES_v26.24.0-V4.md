# MAX Mod v26.24.0 V4 (RuStore) — watch-релиз (WearOS + OnePlus Watch 3)

**Сток:** 26.24.0 (RuStore, RS variant) · **Совместимость:** Android 8.0–16.0 (API 26–36) · arm64-v8a + armeabi-v7a · основной + клон (`ru.oneme.ap2`)

Watch-релиз поверх V3. Портированы доработки из ветки 26.23.2 RS: bounded ScrollView в диалогах, точечное скрытие верхнего индикатора списка чатов, ABI-фильтр обновлятора, 3 кнопки в диалоге проверки обновления, WearOS wearable-метаданные в манифесте. **Весь UI-функционал V3 сохранён, безопасность и приватность не менялись. На телефонах поведение V3 — 1-в-1.** Ставится через `install -r` поверх любой сборки 26.x — данные сохраняются.

## ⌚ Что нового в V4

- **📐 Bounded ScrollView в диалогах мода на часах.** Меню настроек и окно «Проверить обновления» на watchface 466×466 перерастали высоту экрана — кнопки уезжали за край, скролл не работал. Теперь высота ScrollView ограничена 55% `heightPixels` через `FrameLayout$LayoutParams`. На телефонах визуально не заметно.
- **📋 Точечное скрытие `topIndicatorView` (id `0x7f090908`) на часах.** Одноразово через `Handler.postDelayed(600ms)` с гейтом `widthPixels<500`. Ранее использовался стоковый `RootController.o1(Z)` — он скрывал общий контейнер, ломал скролл списка чатов. Финальная реализация (rev4 rev2) — только `findViewById + setVisibility`, скролл не затрагивается.
- **🎯 UpdateChecker выбирает ассет по ABI устройства.** Начиная с V2 в Release 4 APK (arm64/arm7 × main/clone), но старый фильтр искал substring `"arm64-v8a"` — имена V2/V3/V4 содержат `arm64` / `arm7` без `-v8a`. Часы могли схватить arm64-ассет. Теперь: `Build.SUPPORTED_ABIS[0]` → `"arm7"` / `"arm64"`.
- **🔘 Три кнопки в диалоге проверки обновления на часах.** «Нет / Да / Скачать последнюю» в один ряд с уменьшенным padding — влезают на watchface. С корректным `AlertDialog + DialogInterface$OnClickListener` (2-arg сигнатура).
- **🤝 WearOS wearable-метаданные в манифесте.** Через прямой AXML-редактор (без apktool, `resources.arsc` не трогается):
  - `<uses-feature android:name="android.hardware.type.watch" android:required="false"/>`
  - `<meta-data android:name="com.google.android.wearable.standalone" android:value="true"/>`
  - `<meta-data android:name="com.google.android.wearable.notificationBridgeMode" android:value="NO_BRIDGING"/>`

  WearOS-компаньон **не мостит** уведомления с телефона на часовой MAX — пуш приходит локально, без дубля.

## 🐞 Из V3 — сохранено

Отправка фото/файлов (пере-отрезолвленная R8-ссылка `Lts5;→Lew5;`), читаемость окон обновления (`DialogsUtils.tintTextViews` — белый текст на `#2D2D2D`).

## 🆕 Из V2 — UI-рефактор диалогов

Закруглённые диалоги (16dp), нативные RadioButton выбора цвета иконки, класс `DialogsUtils` (в V4 расширен методом `showRoundedExisting` для watch-диалогов через `Builder.create()`), переписанный на −63% экран настроек мода, тема диалогов по системному night-mode.

## 📱 SMS-регистрация — работает

WS-redirect от сервера MAX (шардинг auth-flow по номеру) не блокируется. SMS-код доходит для новых номеров штатно.

## ⚠ Известные ограничения

- **AMOLED** — покрытие ~95% (список чатов и нижние шторки могут остаться тёмно-серыми).
- **Диалоги мода — тёмная схема** (фон фиксированно тёмный для гарантии контраста).
- **Закруглённые диалоги** — best-effort: у отдельных системных диалогов углы могут остаться прямыми.
- **Watch-фичи V4** активны только на устройствах с `widthPixels < 500` (гейт runtime). На телефонах инертны.
